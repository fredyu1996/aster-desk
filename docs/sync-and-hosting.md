## Cloud trader (bot/run.mjs)
- Each run: read the state file → if a **browser** holds the lock and saved <5 min ago, stand by (change nothing) → load the desk's own code in a Node `vm` sandbox with localStorage seeded from the state → load exchangeInfo, tickers, funding, then OI + 15m + 1h candles for top-10 gainers/losers + tracked + open positions + watchlist (~20–25 coins) → restore OI snapshots saved by earlier runs (3 h kept) → **replay 1-minute candles** since the last save for every open position of both traders (5m candles if the gap is >16 h). Each candle is walked open → adverse extreme → favourable extreme → close, and fills at the exact stop/target level crossed (or at the open on a gap), stamped with the candle time → `computeAll`, `periodicChecks`, `trkUpdate`, `ptTick` (Trader, Reviewer, SMC Trader; a pending Reviewer review is read immediately) → the Reviewer's 24h follow-ups (`await rvFollowTick(6)`) → save with lock {dev:'cloud'} plus `pt`, `rv`, `sm`, `trk`, `cfg`, `oi` and `cloud` {t, runs, dur, eq, smEq, smOpen, replayed, open, alerts (last 60 from Trader/Reviewer/GainerLoser/SMC), err}. On failure it writes `cloud.err` so the desk shows it.
- The engine got two hooks for this: `CLOCK_OVR` (now()) and `PX_OVR` (ptPx). Position management: `ptManage(t, only)` / `smManage(t, only)`.
- TZ America/Creston on the runner, so the daily-loss day boundary matches the desk. Actions use checkout@v5 / setup-node@v5, Node 22.
- Aster's API answers GitHub's runners. A run takes ~5–7 s of trading work (~40 s including setup).

## Browser sync (sync.js)
- Top-bar chip: SYNC OFF / SYNCED · TRADING HERE / VIEWING · CLOUD TRADES / VIEWING · <computer>. It opens the Sync panel with a "Cloud trader" card (last run, runs, equity, replayed candles, recent cloud trades/alerts, errors). Cloud alerts also appear in the desk's alert feed prefixed ☁.
- Roles: whoever holds the lock trades. Default with the cloud running: every browser is a viewer (polls the ref every 20 s; Trader/Reviewer/SMC buttons blocked with a "take over first" message). "Take over trading here" → that browser trades every 5 s and saves every 90 s; the cloud stands by while that lock is <5 min old. "Hand trading back to the cloud" writes a cloud lock and the browser becomes a viewer. A browser lock goes stale after 5 min, a cloud lock after 30 min; a viewer auto-takes over a stale lock. Before saving, a trader checks the ref and steps down if someone else took over.
- A browser that saves keeps the cloud's `oi` and `cloud` fields in the file.
- Synced: both paper accounts + logs + equity curves, Reviewer (incl. screening profile), day tracker, settings/watchlist (minus sound/notify). Not synced: browser OI history, recent coin checks.
- Startup bug fixed Nov 8: the desk hung on "Booting…" once the account had closed trades (screens were drawn before the Reviewer code loaded). Each desk's screens are now drawn independently and redrawn after all code has loaded.
